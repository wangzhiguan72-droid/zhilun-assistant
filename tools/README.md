# tools/ · 开发与诊断脚本

这些是**开发期工具**，不属于回归套件（回归套件是根目录的 `*_test.py`）。
它们多数需要**真实 API Key**，或依赖不入库的本地资源，所以单独放置、不参与 CI。

> 从仓库根目录运行，例如 `python tools/tier_verify.py`。

| 脚本 | 用途 | 需要 Key | 说明 |
| --- | --- | :---: | --- |
| `tier_verify.py` | 验证 `free` / `pro` 档位路由到的模型是否正确 | ✗ | 只实例化 Agent 读 `model_name`，**不真调 API**，不耗额度 |
| `test_siliconflow.py` | 硅基流动平台连通性检查 | ✓ | 单平台最小连通测试 |
| `test_router_v4.py` | 端到端验证 V4-Pro / V4-Flash / GLM-Z1-9B 三个模型可用 | ✓ | Key 从 `.env.tmp` 临时读取，不入源码 |
| `test_router_zhipu.py` | 验证智谱接入与容灾回退（无智谱 Key 时应退回 sf） | ✓ | 覆盖三种 Key 组合 |
| `probe_three_platforms.py` | 三平台真调探针 + 隐式前缀缓存命中观测 | ✓ | 会消耗额度 |
| `corpus_scan.py` | 批量扫描 `模板论文/` 下的提取文本，抽查识别层误报 | ✗ | 依赖**不入库**的 `模板论文/` 目录（第三方论文涉版权） |

## 为什么不放进回归套件

- **需要真实 Key**：CI 里没有凭据，跑了也会 skip，意义不大；
  而如果强行 mock，就测不到「真实响应格式与缓存行为」这类最该验证的东西。
- **消耗额度且可能被限流**：LLM 接口有速率限制，批量串跑容易撞 429 或超时。
- **`corpus_scan.py` 依赖版权资源**：`模板论文/` 已列入 `.gitignore`，不进公开仓库。

## 相关约定

- 真调脚本要注意**限流**：`security_guard` 的 LLM 桶默认 8 次/分钟。
  需要连续调用时，在脚本内设 `RATE_LIMIT_DISABLE=1`（**只在需要的脚本内设**，
  不要在共享 harness 里全局设，否则会让限流相关的测试假失败）。
- 报错出口已过 `secrets_guard` 脱敏，但**测试里只允许用合成 Key**。

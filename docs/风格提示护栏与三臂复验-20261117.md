# 风格提示护栏复核与三臂真调复验（v2.61，2026-11-17）

本记录回答一个具体问题：**把模型接入本项目的领域校准提示词后，为什么有些模型反而变差，
修好之后是否真的不再变差。** 所有数字来自本机真调 API 的实测，不是推断，也不是离线模拟。

---

## 1. 问题来源

参赛材料的证据分级表里，这一行被复核判为「不成立」：

> 「中等能力模型接入 Agent 后增益更大」——方向增益与基线 ρ=-0.195（p=0.36）；
> 方向指标 5 个下降、严格指标 6 个下降；最差 MiMo-V2.6-Pro 57.1%→28.6%。

即：旧版领域校准提示词（`agents/prompts.py` 的 `PAPER_CHECK_SYSTEM` + 5 条触发式少样本）
在部分模型上把判定质量拉低了。用户要求先定位原因、改软件提升性能，且**不允许智能体让模型能力变差**；
新版本另起，旧版本保留。

## 2. 诊断：31 条变差样本的四条根因

对第五/六轮 24 个模型的原始逐条结果做翻转分析（脚本 `_agent_gain_20261117/diagnose.py`，
产物 `诊断_逐条翻转.csv` / `诊断_逐模型.json`）：

- 共 112 条判定发生翻转：**变好 49 / 变差 31 / 中性 32**。
- 31 条变差的构成：

| 成因 | 条数 | 说明 |
| --- | --- | --- |
| 单项被动判真 | 15 | 方法/实验程序段只有「被动句偏多」一个触发，被判为风格问题成立 |
| 方法/结果段多触发判真 | 10 | 术语表述被当成空泛套话，叠加被动句后判真 |
| 漏真 | 5 | 全部集中在第 12 条（C44，人工唯一的「真」），旧垂直臂判假 |
| 判词与理由矛盾 | 1 | MiMo 第 19 条：判词与给出的理由互相矛盾 |

四条根因：

1. **问法错了。** 旧 `TEMPLATE` 问「该风格提示是否成立」，少样本写成
   「触发：X｜摘录：Y → 判 Z」。模型学到的是**核对触发词在不在**，
   而不是**问题成不成立**——触发词在就判真。
2. **豁免规则交给了模型。** 封面/版权页、方法段单项被动、参考文献条目本该由代码确定性豁免。
   本地其实早有这条规则：`ai_audit.py:383` 用 `_METHOD_MARK_RE`（定义在 `ai_audit.py:355`）
   抑制方法段的单项被动。但实验用的是 v2.51 之前的旧触发集合，绕过了这道本地抑制，
   把豁免判断整个丢给了模型。
3. **不确定性被塌缩成「假」。** 摘录只有 201 字符，旧提示词又写死「只有…才判真」，
   模型在证据不足时直接判假，而不是保留未判定——第 12 条的 5 次漏真就是这么来的。
4. **没有判词/理由一致性检查。** 矛盾输出原样进入统计。

## 3. 修复：v2.61 本地豁免门 + 分解式提问 + 本地合成

新增 `style_triage.py`（`GATE_VERSION = "v1"`，`TRIAGE_PROMPT_VERSION = "v1"`）。
设计原则一句话：**模型负责识别，本地负责定性。**

- **本地豁免门** `local_gate`（`style_triage.py:109`）：封面/版权页需字段族 ≥3
  **且**呈字段清单排版（`_is_field_layout`，`style_triage.py:97`，避免正文提到
  「学位论文/研究方向/培养单位」就被误豁免）；方法段单项被动沿用 `_METHOD_MARK_RE`；
  参考文献条目按条目正则。**豁免项一次模型都不调。**
- **分解式提问** `STYLE_TRIAGE_SYSTEM`：不再给触发式少样本，改问两件事——
  ①这些现象在摘录里**是否可见**、属什么段落类型；②**是否需要作者修改**、证据是否充分。
- **本地合成** `reconcile`（`style_triage.py:221`）：按
  本地豁免门 → 模型识别的段落类型二次门 → 学科惯例维度扣除 → 输出不可解析 →
  判词理由矛盾 → 本地无作者可控证据 / 现象不可见 → 本地与模型分歧 →
  模型未确认 → 密度型信号护栏 → 真 的顺序合成。
- **判真的硬条件**：必须同时有本地作者可控证据 **和** 模型确认可见；
  在方法/结果/程序段还必须有窗口内可判定的**硬事实维度**
  （`HARD_FACT_DIMENSIONS`，`style_triage.py:60`；「空泛套话」是密度型信号，不算硬事实）。
  这条专门修第 14 条「起到中介作用」被当空话的回归。
- **证据不足一律「存疑」，绝不塌缩成「假」**；模型意见原样保存在 `model_opinion`，不被覆盖。
- **单条失败回落本地**，整批模型不可用也**绝不丢条**（`triage_batch`，`style_triage.py:380`）。

产品接线：

- `/api/ai_audit` 出口套 `apply_gate`（`app.py:3616`）：豁免段落移入 `passages_exempted`
  并附豁免依据，建议语与优先级同步改写，报告带 `gate_version`。
- 新增 `/api/style_triage`（`app.py:3652`）：`llm=false` 时零模型调用；
  返回逐条判词、来源、本地证据、模型意见、护栏、调用次数与版本号。
- 路由新增 `style_triage` 状态（`agents/router.py:122`），温度 0.2 与实验一致，免费档优先。
  该状态**不走** `paper_check` 的冻结前缀缓存契约（输入是 ≤200 字摘录 + 现象清单）。
- 前端 `templates/index.html` 增加豁免清单与护栏复核结果区；
  契约探针 `_syntaxcheck/style_triage_probe.js`（含 XSS 转义与失败态按钮恢复）。
- `desktop.spec` datas 补 `style_triage.py`；`version.py` 改一行 v2.61。

**旧版本完整保留**：`agents/prompts.py`、`llm_audit.py`、`ai_audit.py` 三个文件本轮**未改动**
（`style_triage_test.py::OldVersionPreservedTest` 逐字断言旧提示词仍在）；
旧可执行文件另存为 `dist/智论助手-v2.60-保留.exe`（100,128,963 字节）。

## 4. 复验方法

脚本 `_agent_gain_20261117/verify_arms.py`（网关 8 模型）与
`_agent_gain_20261117/verify_mimo_official.py`（小米官方 2 模型），三臂同题对照：

| 臂 | 系统提示词 | 本地护栏 |
| --- | --- | --- |
| `generic` | 旧通用提示词（裸模型） | 无 |
| `vertical` | 旧领域校准提示词 + 5 条少样本 | 无 |
| `guarded` | v2.61 分解式提示词 | 有 |

- 同 28 条风格提示、同 201 字符摘录、同 `temperature=0.2` / `max_tokens=2000`。
- 旧两臂提示词用 `importlib` 从第六轮原文件 `llm_vertical_matrix_r6.py` **直接导入**，逐字一致，避免抄写漂移。
- 人工标签取自 `复核台账-2026-10-21.csv`：**假 8 / 存疑 19 / 真 1**（真只有第 12 条 C44）。
- 指标口径与 r6 `score()` 一致：严格一致率、方向一致率（`(v=='真')==(lab=='真')`）、
  特异度、假族覆盖、漏真 FN。
- 网关：本机 magpie `http://127.0.0.1:3425/v1/chat/completions`（8 个模型）。
- 小米官方：`https://api.xiaomimimo.com/v1`，**OpenAI 兼容协议**，经产品自己的
  `agents/mimo_agent.py` 直调（2 个模型）。平台另有 Anthropic 兼容端点与批量推理端点，
  都不在产品链路里，不用；Key 走 `MIMO_API_KEY`，只存本机 `.env`（已 gitignore）。

- `agents/mimo_agent.py`：登记 `mimo-v2.6-flash` / `-pro` / `-pro-ultraspeed`，
  下线 ID 就近映射（`mimo-v2.5`→flash、`mimo-v2.5-pro`→pro），默认档改 flash。
- `agents/router.py`：6 个状态的 MiMo 候选全部换成现役 ID；`VISION_MODELS` 去掉
  早已不存在的 `mimo-vl` 与 v2.5，换成**实测读图通过**的三档 v2.6
  （图里画唯一数字 7391 + 紫色矩形，三档都读对了数字与颜色）。
- `kimi_mimo_test.py` 补两条回归：下线 ID 必须映射到现役模型；
  **路由表里不得出现下线 MiMo 候选**（别名映射只在 Agent 层生效，表里留死 ID 会让
  `VISION_MODELS` / `FREE_MODELS` 这些按 ID 比对的门全部失配）。

### 实验路径与产品路径是否同一套代码

是。两边都走 `style_triage.triage_passage` / `triage_batch`，
提示词都由 `build_triage_prompt` + `STYLE_TRIAGE_SYSTEM` 生成，判词都由同一个 `reconcile` 合成。
差别只有两处，且都不影响可比性：

- 网关 8 模型直连本机 magpie 做三臂对照；小米 2 模型**经产品 `MimoAgent` 直调官方平台**，
  与产品走的是同一个适配器（同一套超时放宽、空内容防护、别名解析）。
  产品运行时再经 `agents/router.py` 的 `style_triage` 状态做多提供商回落。
- 实验 `max_tokens=2000`（与旧两臂逐字对齐，保证唯一差异是提示词与护栏）；
  产品 `max_tokens=4096`（思考型模型小预算会被思考吃光）。预算更大只会更宽松，不会更严。

## 6. 严格指标那 7 条变差，逐条说明（不调参掩盖）

| 条目 | 人工 | 裸模型 | 护栏 | 来源 | 涉及模型 |
| --- | --- | --- | --- | --- | --- |
| #2 C17 | 假 | 假 | 存疑 | `no_local_evidence` | DeepSeek |
| #4 C19 | 假 | 假 | 存疑 | `no_local_evidence` | DeepSeek、MiniMax、GPT-OSS、**MiMo-Pro** |
| #6 C19 | 存疑 | 存疑 | 假 | `not_visible` | DeepSeek |
| #15 C44 | 存疑 | 存疑 | 假 | `local_gate` | DeepSeek |

- **#2 / #4（5 条）**：摘录本身是截断的访谈引语与参考文献碎片
  （#2 止于一个被截断的音译人名，#4 止于半句假设陈述）。查这 5 次判定的 `model_opinion`，
  **模型自己全部报 `evidence_sufficient` 为「否」或「无法判断」**（含新增的 MiMo-Pro #4），
  理由明写「摘录被截断」。护栏在这种情况下拒绝断言「提示不成立」，保留存疑——
  这正是根因 3 要修的行为。人工的「假」是看完整段落打的，摘录窗口看不到。
  **这是设计取舍，不是缺陷，不为了指标把它调回「假」。**
- **#6 / #15（2 条）**：护栏比人工的「存疑」更果断。#15 是方法段单项被动，
  本地有确定性依据（段落标记 + 单一维度）判学科惯例不适用；#6 是模型明确确认现象不可见且证据充分。
  有依据的「不成立」比「拿不准」信息量更大，方向指标不受影响。

护栏 vs 旧垂直同样是 7 条变差，但构成不同：#2（DeepSeek、MiniMax）、
#4（DeepSeek、GPT-OSS、MiniMax、MiMo-Pro）共 6 条同上；
另 1 条是 **#21（GPT-OSS，人工存疑，旧垂存疑→护栏假，`local_gate`）**，与 #15 同类。
旧垂直臂在这 7 条上「精确命中」，靠的是把截断摘录也断言成「假」——正是本轮要修的行为。

**假族覆盖**（人工「假」8 条中被精确判「假」的比例）如实报告：
GLM 100、Gemini-3.1 100、Kimi 100、Step-5 100、**MiMo-Flash 100**、

**严格一致率整体偏低（32.1–50.0）的原因也要说清**：人工台账 28 条里 19 条是「存疑」，
而护栏在有确定性依据时果断判「假」（`local_gate` 180 条中 120 条人工标存疑、60 条标假；

### 12.5 第一轮审计有盲点，补扫后又清掉一批（如实记录）

1. **中文路径被静默跳过。** `git status --porcelain` 默认把非 ASCII 路径写成八进制转义
